# ADR 001: 開発環境・技術スタックおよびバージョン選定

- 日付: 2026-11-25
- ステータス: 採用

---

## 背景・課題

社内向け Web サービス「CorpDesk」（利用者 100〜300 名規模を想定）を React + TypeScript + Laravel（PHP）+ MySQL で構築するにあたり、以下を満たす開発環境とバージョン選定が必要になった。

- ホストマシン（`nuc7`）に PHP が未導入でも、ワンコマンドで再現可能な環境であること
- セッションベース認証（Laravel Sanctum）を安全かつシンプルに扱えること
- サポート切れ（EOL）やリリース直後の不安定バージョンを避け、実務に近い保守性の高いバージョンを選定すること

## 検討した選択肢

### 1. フロントエンドとバックエンドの接続方式
1. **案A: Nginx リバースプロキシによる同一オリジン構成（採用）**
   - メリット: ブラウザから `/`（React/Vite）も `/api/*`（Laravel）も `http://localhost:8080` の同一オリジンになるため、複雑な CORS 設定やクロスサイト Cookie（`SameSite=None` 等）の罠を回避でき、本番構成にも近い。
   - デメリット: Nginx 設定（`default.conf`）と Vite HMR 用 WebSocket プロキシ設定を書く手間が増える。
2. **案B: Vite（5173）と Laravel（8000）を別ポートで直接公開**
   - メリット: Nginx 不要で初期構築が簡単。
   - デメリット: CORS と Cookie 認証の環境差異が出やすく、本番構成との乖離が大きい。

### 2. PHP / MySQL のバージョン選定
1. **PHP**:
   - **PHP 8.4（採用）** / 8.5: Laravel 12・13 および Larastan 等の周辺エコシステムが正式対応済みで安定している。
   - **PHP 8.6（見送り）**: 2026年11月19日リリース直後であり、フレームワーク・主要パッケージの対応が追いついていないため、依存関係トラブルのリスクが高い。
2. **MySQL**:
   - **MySQL 8.4 LTS（採用）**: 現行の長期サポート版で、新規構築・本番運用の標準。
   - **MySQL 8.0（見送り）**: 2026年4月に EOL（サポート終了）を迎えており、新規採用すべきでない。

## 決定内容とその理由

- **Docker Compose（Nginx + PHP-FPM 8.4 + MySQL 8.4 LTS + Node 26 LTS / Vite）** を採用する。
- Nginx を前段に置き、`/api/` と `/sanctum/` を PHP-FPM（`php:9000`）へ、それ以外を Vite（`frontend:5173`）へ振り分ける同一オリジン構成とする。
- これにより、開発環境の再現性を担保しつつ、実務の社内 Web サービスに近い認証・ルーティング構成で学習と検証を行える。

## トレードオフ・今後の課題

- 開発時は Vite Dev Server へプロキシする構成としているが、本番ビルドを想定する場合は Nginx から静的アセット（`frontend/dist`）を直接配信する構成に切り替える必要がある。
- Docker コンテナ上のファイル権限（ホストとコンテナ間の UID 差異）による書き込みトラブルが起きた場合は、ユーザーマッピングの調整を検討する。
