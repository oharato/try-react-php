## 1. 12月5日(土) オンライン会社説明会 確認リスト

説明会に参加したら、以下のメモを取り、必要であれば Phase 3〜4 の実装や README の訴求ポイントを微調整する。

- [ ] 再応募の可否・選考上の注意点はあるか
- [ ] 社内 Web サービスで使われている React / PHP のバージョンやフレームワーク（Laravel / Symfony / 素のPHP など）
- [ ] 利用している DB（MySQL / PostgreSQL 等）やインフラ（オンプレ / AWS 等）
- [ ] 現在もっとも課題に感じている社内システム領域（例: レガシー刷新、新規社内ツール企画、業務自動化など）
- [ ] コーポレートウェブ SE に特に求める人物像・コミュニケーションスタイル

---

## 2. 非エンジニア社員を意識した UX 磨き込みチェックリスト

ゲーム開発者・デザイナー・総務など多様な社員が毎日使う前提で仕上げる。

- [ ] ローディング中に画面がガタつかない（スケルトン表示やボタンの二重送信防止 `isPending` 制御）
- [ ] バリデーションエラーが「どの項目をどう直せばいいか」具体的な日本語で出る
- [ ] 空状態（データ0件時）に次のアクションが案内されている
- [ ] 主要な操作がキーボードでもストレスなく行える（フォーカス順序・Enter送信・Escでモーダル閉じる）

---

## 3. ポートフォリオ `README.md` に必ず載せる項目

採用担当者はコード全体を隅々まで読む時間が限られるため、トップの `README.md` で勝負を決める。

1. **背景と目的**: なぜ社内ITサポート＆備品管理ポータルを作ったか
2. **技術スタックと構成図**: Mermaid 図で一目瞭然にする
3. **ER 図と DB 設計のポイント**: 正規化・複合インデックス・排他制御
4. **主な工夫点（3〜5個）**:
   - Vue.js 実務経験を活かした React + TanStack Query 設計
   - 二重貸出を防ぐトランザクション・排他制御とテスト
   - 150名・1,000件データでの N+1 解消と `EXPLAIN` 検証
   - 社員サポート目線の FAQ サジェスト UX
   - Docker Compose + CI（PHPStan / PHPUnit / Vitest）による再現性と品質担保
5. **画面スクリーンショット（3〜4枚）**: 機材一覧・申請画面・問い合わせ＆FAQサジェスト
6. **ローカル起動手順**: `docker compose up -d` からの3コマンド以内

## 4. 職務経歴書への記載方針（ハル研再応募向け）

職務経歴書の「技術スキル」および「個人開発・直近の取り組み」セクションに以下を明記する。

- GitHub リポジトリ URL（`try-react-php` を公開または適切な名称で整備）
- 使用技術: **HTML / CSS / TypeScript / React / PHP / Laravel / MySQL (SQL) / Docker**
- 「現職の Vue.js / TypeScript / PHP / Java / DB設計の実務経験を基盤に、貴社技術スタック（React + TypeScript + PHP + SQL）を用いた100名以上規模想定の社内Webサービスを設計・実装」と明確に紐づける。
